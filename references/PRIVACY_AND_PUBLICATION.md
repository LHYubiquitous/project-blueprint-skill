# Privacy & Publication Policy

在任务涉及本地项目、未公开构思、真实账户、联网检索、共享或开源发布时读取本文件。

## 1. 数据范围最小化

默认允许使用：当前对话、用户在本任务中提供的附件、用户明确指定的项目目录，以及完成任务必需的公开来源。

默认不得探索：用户主目录、父目录、其它仓库、云同步盘、浏览器资料、聊天历史、邮件、通讯录、密钥链，以及 `.ssh`、`.aws`、`.config` 等凭据或配置目录。工具能够访问某个位置不代表任务已授权读取它。

仅收集会改变需求、设计或验证结果的信息。遇到凭据时不要复制、显示或写入产物；若凭据可能已经进入版本历史或外部系统，应提示用户撤销/轮换，而不是仅删除当前文件。

## 2. 外部检索与第三方服务

联网搜索会把查询发送给外部服务。提交前：

1. 删除姓名、邮箱、账号、客户/组织名称、设备名、内部域名、仓库路径和工单编号。
2. 将私有项目代号、完整错误信息、日志和代码改写为足以检索的通用技术描述。
3. 不提交凭据、签名 URL、私有源码、私有文档原文或可逆推出身份的独特组合。
4. 如果去掉这些信息会让任务无法完成，先说明将发送给哪个服务、发送什么，再取得明确授权。

公开资料的 URL、开源项目名称和一般技术关键词通常可以直接检索。

## 3. 文档中的脱敏规则

| 原始信息 | 默认写法 |
|---|---|
| `<home>/work/private-repo` | `<repo-root>` 或仓库相对路径 |
| 真实姓名、邮箱、账号 ID | `User A`、`Account A` 或角色名称 |
| 内部主机名、私有 URL | `<internal-service>` |
| Token、密码、Cookie、私钥、签名查询串 | 不写入；必要时只写秘密管理器中的引用名称 |
| 完整日志或截图 | 仅保留支持结论的脱敏片段 |
| 私有 Git 远端与提交 | 仅在交接确有需要且分享范围允许时记录 |

测试应优先使用合成数据。真实账户和数据只能在用户授权的集成测试中使用，测试报告不得包含原始标识或秘密。

## 4. 发布与开源 Gate

本地创建、Git commit、推送到私有远端、公开仓库和向第三方上传是不同授权动作。执行公开发布前必须：

1. 确认用户明确要求公开发布以及目标仓库/服务。
2. 只包含当前项目文件，不打包父目录、编辑器状态、缓存、日志、下载物或本地配置。
3. 确认所有文本、代码、模板和素材由发布者拥有或已按兼容许可证获得授权；保留必要的版权和第三方通知。
4. 检查项目名称、截图、样例数据和提交历史是否泄露个人、客户、组织或内部系统信息。
5. 运行 `python scripts/audit_publication.py <directory>`，处理所有命中，再人工检查 diff、文件清单与 Git 历史。
6. 确认远端可见性、默认分支和许可证符合用户要求后再推送。

扫描器是保守的辅助工具：它可能误报，也无法发现所有商业机密、复制来源或语义上的隐私信息。扫描通过不等于获得发布授权，也不等于完成知识产权审查。
